## Что это за продукт
Сервис гаданий на Таро внутри Telegram. Пользователь открывает Mini App, выбирает расклад, задаёт вопрос, вытягивает карты, получает ИИ-трактовку. Есть карта дня, история, профиль с балансом, пополнение, 2 колоды, натальная карта. Монетизация: баланс в рублях, расклады платные (15–100 ₽), один бесплатный простой расклад в день.

## Архитектура и безопасность (критично)
Клиент НЕ должен быть источником истины. Всё, что влияет на деньги и результат, делает сервер:
1. **Авторизация Telegram.** На каждом запросе из Mini App приходит `initData`. Валидируй подпись HMAC-SHA256 по bot token (алгоритм Telegram WebApp). Из `initData` бери `user.id`, имя, username, photo_url. Никогда не доверяй профилю/балансу с клиента. Сделай middleware, кладущий verified `userId` в контекст. Заведи короткоживущую сессию/JWT после первичной валидации, чтобы не валидировать initData на каждый чих (но проверяй срок).
2. **Розыгрыш карт — на сервере.** Клиент только анимирует. Сервер выбирает `count` уникальных карт (крипто-случайность), решает перевёрнутость (~35%), сохраняет расклад.
3. **Списание — атомарно в транзакции БД.** Проверка права (free/баланс) и списание — в одной транзакции, чтобы не было гонок/двойных списаний.

## Модель данных (Prisma) — отрази README
- `User`: `tgId (unique)`, `firstName`, `username`, `photoUrl`, `balance (Int, копейки или рубли — выбери и задокументируй)`, `deck (enum mansion|wood|classic, default mansion)`, `freeUsedDate (Date?)`, `dayRevealedDate (Date?)`, `createdAt`.
- `Transaction`: `userId`, `type (topup|spend|free)`, `title`, `amount (Int, +/–/0)`, `createdAt`.
- `Reading`: `userId`, `spreadId`, `question`, `cards (Json — массив {n, reversed})`, `interpretation (Json — {cards:[], summary})`, `extra (Json? — данные пары/натала)`, `createdAt`.
- `Payment`: `userId`, `provider`, `providerPaymentId`, `amount`, `bonus`, `status`, `createdAt`.
Засей справочники из `data.js`: `SPREADS`, `TOPUP`, `ARCANA` (78 карт + тексты), `CARD_DESC`, `DECKS`. Карты-картинки (`cards/mansion`, `cards/wood`) — раздавай как статику/CDN.

## API (минимум)
- `POST /api/auth` — принять `initData`, валидировать, апсертнуть пользователя, вернуть сессию + профиль + баланс.
- `GET  /api/me` — профиль, баланс, статус бесплатного расклада, выбранная колода.
- `GET  /api/catalog` — расклады, цены, пакеты пополнения, колоды (из сидов).
- `POST /api/reading` — `{ spreadId, question?, extra? }`. Сервер: проверка права → списание (free/баланс/иначе 402 «не хватает N₽») → розыгрыш карт → вызов LLM → сохранить `Reading` → вернуть `{ cards, interpretation, balance }`. Это покрывает экран ожидания «маг думает».
- `GET  /api/history` — список гаданий пользователя (с картами и трактовкой для просмотра).
- `GET  /api/daily` / `POST /api/daily/reveal` — карта дня (детерминирована по дате, фиксируется на пользователя).
- `POST /api/deck` — сменить колоду.
- `POST /api/natal` — `{ name, date, time, place }` → построить натальную карту (см. ниже) после списания 100 ₽.
- **Платежи:** `POST /api/topup/create` (создать платёж по `packageId`) + вебхук провайдера `POST /api/payments/webhook` → по подтверждению начислить `amount+bonus`, записать `Transaction(topup)` и `Payment`.
