# Handoff: Таро Премиум — Telegram Mini App

## Overview
«Таро Премиум» — это сервис онлайн-гаданий на Таро, оформленный как **Telegram Mini App** (вертикальный экран телефона, тёмная мистическая luxe-эстетика). Пользователь выбирает расклад, задаёт вопрос, вытягивает карты из анимированной колоды, и получает персональную ИИ-трактовку. Есть карта дня, история гаданий, профиль с балансом, пополнение, переключение колод и натальная карта.

Этот бандл — **результат проектирования фронтенда и UX**. Цель разработчика: реализовать **бэкенд** (Telegram-авторизация, реальные платежи, серверный вызов ИИ, БД) и собрать прод-приложение, повторив этот фронтенд в боевом окружении.

## About the Design Files
Файлы в этом бандле — **дизайн-референс, написанный на HTML/React (через Babel в браузере)**. Это рабочий прототип, показывающий итоговый внешний вид и поведение, **а не прод-код для прямого копирования**. Задача — **воссоздать эти экраны в боевом стеке** (рекомендуется React + TypeScript, т.к. прототип уже на React; либо ваш существующий стек/фреймворк Telegram Mini App), используя его паттерны, и **дописать бэкенд**, которого в прототипе нет.

В прототипе всё состояние хранится в `localStorage` и ИИ вызывается через встроенный браузерный хелпер `window.claude.complete`. В проде это заменяется на серверную БД и серверный вызов LLM с вашим API-ключом.

## Fidelity
**High-fidelity (hifi).** Цвета, типографика, отступы, анимации и интерактив — финальные. Воспроизводите UI попиксельно. Раздел «Design Tokens» ниже содержит точные значения; полный источник стиля — `<style>` в `index.html`.

## Архитектура и карта файлов

## Поток приложения (роутинг)

Состояние маршрута — объект `{ name, ... }` в `app.jsx`. Переходы:

```
home ──tap расклад──> [charge]
   │                    │ нет денег ─> topup (с need)
   │                    │ ok
   ├─ natal ───────────> natal ─(форма)─> wheel+интерпретация
   ├─ daily ───────────> deck ─> thinking ─> reading
   ├─ love / match ────> pairform ─(данные пары)─> deck ─> thinking ─> reading
   └─ остальные ───────> question ─(текст вопроса)─> deck ─> thinking ─> reading

reading ─(«новый»)─> home
history ─(tap запись)─> reading (просмотр прошлого)
profile ─(пополнить)─> topup ─> profile
```

Нижняя навигация: **Главная · История · Профиль**.

## Экраны / Views

> Точная разметка, размеры и инлайн-стили — в соответствующих `.jsx`. Ниже — назначение, состав и поведение каждого экрана.

### 1. HomeScreen (`screens-core.jsx`)
- **Назначение:** витрина. Шапка с названием «Таро Премиум · Оракул судьбы», балансом (кликабелен → профиль) и индикатором бесплатного расклада.
- **Карта дня:** одна карта, переворачивается по тапу (flip-анимация). Раскрытие фиксируется на день (`localStorage tl_day`). Выбор карты дня детерминирован по дате: `ARCANA[parseInt(YYYYMMDD) % ARCANA.length]`.
- **Блок «Расклады Таро»:** сетка 2 колонки, 6 простых раскладов (`group:'simple'`). Каждый тайл: обложка-карта (реальная иллюстрация выбранной колоды по `SPREAD_COVER`), название, подзаголовок, цена/бейдж «Бесплатно сегодня».
- **Блок «Премиальные»:** 3 горизонтальных баннера ~3:5 в 1 строку (`group:'big'`): Кельтский крест, Прогноз на год, Натальная карта. С переливающимся бликом (`.sheen-band`).
- **Блок «Как это работает»:** 3–4 шага.
- **Соцсети:** Instagram (`https://instagram.com/taro.lux`) и Telegram (`https://t.me/tarolux_bot`), `target=_blank`. **← подставить реальные ссылки.**

### 2. QuestionScreen (`screens-core.jsx`)
- Ввод свободного текстового вопроса. Textarea + кнопка «Перейти к колоде». Показывается для раскладов, кроме `daily`, `natal`, `love`, `match`.

### 3. PairFormScreen (`screens-extra.jsx`)
- Для **Отношений** (`love`) и **Совместимости** (`match`).
- Два блока: для `love` — «Вы» / «Партнёр»; для `match` — «Первый человек» / «Второй человек». В каждом: **Имя** (обяз.), **Дата рождения**, **Город рождения** + необязательный общий вопрос.
- Кнопка «Перейти к колоде» активна только когда заполнены **оба имени**.
- Данные уходят в `extra` и используются в ИИ-промпте (обращение по именам, синастрия по датам/городам). Если вопрос пуст — генерируется автоматически («Насколько совместимы X и Y?»).

### 4. DeckScreen (`screens-core.jsx`)
- Выбор карт «как на столе»: горизонтальная дуга/веер рубашек, свайп или стрелки ‹ ›, кнопка **тасовки** и **«Довериться случаю»**.
- **Механика выбора:** тап по карте вытягивает её (с поворотом 720° в слот). Свайп листает и не вытягивает (флаг `moved`).
- **«Довериться случаю»:** золотая вспышка (`fateGlow`) → колода собирается в светящуюся стопку → оставшиеся карты по очереди вылетают в слоты → авто-переход.
- Кол-во требуемых карт = `spread.count`. По заполнению → `onComplete`.

### 5. ThinkingScreen (`screens-core.jsx`)
- Экран ожидания «маг думает» (~2.6 c в прототипе). В проде — пока идёт серверный запрос ИИ.

### 6. ReadingScreen (`screens-extra.jsx`) — ключевой
- Карты раскрываются по очереди (flip). Слева у каждой позиции — миниатюра карты; тап по карте увеличивает её (зум-оверлей).
- Для `verdict`-раскладов (Да/Нет) крупно выводится **ДА/НЕТ** (ДА = прямая карта, НЕТ = перевёрнутая).
- **ИИ-трактовка:** по завершении раскрытия один запрос к LLM возвращает JSON с трактовкой каждой позиции + общий вывод «Слово мага». Во время ожидания — пульсирующая точка и мерцающие скелетоны. См. «Контракт ИИ» ниже.

### 7. HistoryScreen (`screens-extra.jsx`)
- Список прошлых гаданий (расклад, вопрос, дата, набор карт). Тап открывает `ReadingScreen` в режиме просмотра.

### 8. ProfileScreen (`screens-extra.jsx`)
- Профиль из Telegram (аватар/инициалы, имя, username). **В проде заполнять из Telegram WebApp initData.**
- **Баланс** + кнопка «Пополнить».
- Статус бесплатного расклада (доступен / завтра).
- **Переключатель колоды:** 3 варианта (Dark Mansion / Dark Wood / Мистическое золото), превью, сохраняется.
- Статистика (всего гаданий, любимый расклад) и **история трат** (транзакции).

### 9. TopUpScreen (`screens-extra.jsx`)
- 4 пакета пополнения (см. `TOPUP`), выбор по умолчанию `t300`. Кнопка покупки. **В проде — реальная оплата (см. чеклист).**

### 10. NatalScreen (`natal.jsx`)
- Форма: имя, дата рождения, время, место. Кнопка «Построить карту».
- Анимированное **колесо гороскопа** (SVG, рисуется по данным рождения; линии-аспекты детерминированы). Затем секции: Большая тройка (Солнце/Луна/Асцендент), Баланс стихий, Планеты — с развёрнутыми текстами. Цена 100 ₽.

## Модель данных

### Карта (`ARCANA[]`, `data.js`)
78 карт. Старшие Арканы (0–21) и Младшие (22–77, по мастям wands/cups/swords/pentacles).
```js
{ n: 13, rom: 'XIII', name: 'Смерть', glyph: 'death',
  key: 'Завершение, трансформация, обновление',
  up:  'Текст для прямого положения…',
  rev: 'Текст для перевёрнутого положения…',
  // у Младших также: suit:'cups', rank:… }
```
- `card-desc.js`: `CARD_DESC[deckId][n]` — официальное описание карты для конкретной колоды.

### Расклад (`SPREADS`, `data.js`)
```js
yesno: { id, title, cat, count, price, free1card?, accent, verdict?, group:'simple'|'big',
         sub, positions:[...] }
```
Полный список (цены в ₽):

| id | Название | Карт | Цена | Группа | Особенность |
|---|---|---|---|---|---|
| `daily` | Карта дня | 1 | **0** | simple | бесплатно всегда |
| `yesno` | Да или Нет | 1 | 15 | simple | `verdict:true`, `free1card:true` |
| `question` | Вопрос картам | 3 | 15 | simple | Прошлое·Настоящее·Будущее |
| `love` | Отношения | 5 | 15 | simple | → PairForm |
| `situation` | Ситуация | 5 | 15 | simple | |
| `match` | Совместимость | 5 | 15 | simple | → PairForm |
| `money` | Деньги и карьера | 5 | 15 | simple | |
| `celtic` | Кельтский крест | 10 | 30 | big | |
| `year` | Прогноз на год | 12 | 30 | big | позиции = 12 месяцев |
| `natal` | Натальная карта | 0* | 100 | big | особый экран, без вытягивания карт |

\* `count:0` — натальная не использует вытягивание из колоды.

### Пакеты пополнения (`TOPUP`, `data.js`)
```js
{ id:'t50',  amount:50,  bonus:0 }
{ id:'t150', amount:150, bonus:15,  badge:'+15₽' }
{ id:'t300', amount:300, bonus:45,  badge:'+45₽', best:true }   // по умолчанию
{ id:'t700', amount:700, bonus:140, badge:'+140₽' }
```
Зачисляется `amount + bonus`.

### Колоды (`DECKS`, `data.js`)
```js
{ id:'mansion', title:'Dark Mansion', kind:'image', path:'cards/mansion' }  // по умолчанию
{ id:'wood',    title:'Dark Wood',    kind:'image', path:'cards/wood' }
{ id:'classic', title:'Мистическое золото', kind:'art' }                    // рисованные карты
```
`kind:'image'` → лицо карты = `${path}/${n}.jpg` (рамка/номер/имя уже в картинке). `kind:'art'` → рисованный line-art (`CardFace` в `cards.jsx`). Превью/обложки берут карту по `SPREAD_COVER[spreadId]`.

## Бизнес-правила (экономика) — `app.jsx`

- **Один бесплатный расклад в день:** доступен, если `freeUsed !== today` (today = `YYYY-MM-DD`). Распространяется только на расклады с `free1card:true` (сейчас — `yesno`). Карта дня (`daily`) бесплатна всегда. *(Уточнение от заказчика: бесплатно раз в день — только простые расклады в 1 карту.)*
- **Списание (`charge`)**:
  1. `price === 0` → бесплатно.
  2. бесплатный доступен и `free1card` → отметить день использованным, записать транзакцию `type:'free'`.
  3. иначе если `balance >= price` → списать, транзакция `type:'spend'`.
  4. иначе → редирект на `topup` с сообщением «Не хватает N ₽».
- **Пополнение (`doTopup`)**: `balance += amount + bonus`, транзакция `type:'topup'`.
- **Вытягивание (`makeDraw`)**: случайные `count` карт без повторов; перевёрнутость с шансом ~35%, если включён твик `reversible`.

**В проде все эти операции должны выполняться на сервере атомарно** (нельзя доверять клиенту баланс/бесплатность/розыгрыш карт).

## Контракт ИИ-трактовки (главное для бэкенда) — `screens-extra.jsx` → `ReadingScreen`

В прототипе вызывается `window.claude.complete(prompt)`. **В проде это переносится на сервер** (ваш ключ OpenAI/Anthropic), а Mini App дергает ваш эндпоинт.

### Входные данные, собираемые для промпта
- Название и размер расклада, выбранная колода.
- Вопрос пользователя.
- Для пар (love/match) — блок с именами/датами/городами обоих.
- По каждой позиции: номер, название позиции, заголовок карты, перевёрнутость, ключ (`key`), официальное описание (`CARD_DESC[deck][n]`, обрезано до ~260 симв.).

### Длина ответа масштабируется по размеру расклада
- `count >= 10` (большой): по карте **3–4 предложения**, итог **5–7 предложений**.
- `count >= 5` (средний): по карте 2–3, итог 4–5.
- иначе: по карте 2–3, итог 3–4.

### Промпт (точный шаблон из кода)
```
Ты — мудрый, тёплый и красноречивый таролог. Сделай глубокую трактовку расклада
на русском, обращаясь на «вы».
Расклад: «{title}» ({N} карт). Колода: «{deckTitle}».
Вопрос человека: "{question}"
{Опционально: Люди в раскладе: {labelA} — {имя, род. дата, город}; {labelB} — …}
Выпавшие карты:
1. Позиция «{pos}»: {заголовок карты}{ (перевёрнутая)}. Ключ: {key}. Смысл: {desc}
2. …

Это {большой и важный|значимый} расклад — дай развёрнутую, насыщенную и интересную
для чтения трактовку. По КАЖДОЙ позиции напиши {N предложений}: что означает карта
именно в этой позиции и в контексте вопроса, как она влияет на ситуацию, и что с этим
делать. Свяжи карты между собой в единую живую историю, учитывай позиции, соседство
карт и перевёрнутость. Пиши образно и тепло, без «воды» и канцелярита.
Верни СТРОГО валидный JSON без markdown и пояснений, по схеме:
{"cards": ["трактовка позиции 1 (…)", "…"], "summary": "цельный вывод и конкретный совет (…)"}
```

### Ожидаемый ответ (JSON)
```json
{ "cards": ["...по числу карт..."], "summary": "общий вывод и совет" }
```
- Клиент срезает возможные ```` ```json ```` обёртки и берёт подстроку от первого `{` до последнего `}`.
- **Фолбэк:** если ИИ недоступен или JSON не распарсился — показываются статические тексты `card.up/rev` и локальная `summarise()`. В проде стоит сохранять последний удачный результат для истории.

## Натальная карта — логика (`natal.jsx`, `natal-data.js`)
- Знак Солнца вычисляется точно по дате рождения; остальные параметры (Луна, Асцендент, планеты, баланс стихий) — **детерминированно** из даты/времени/места (сид от введённых данных), чтобы результат был стабильным и воспроизводимым для одного человека.
- Колесо рисуется SVG; линии-аспекты тоже детерминированы (одинаковы при тех же данных, различаются у разных людей).
- Это **не астрономически точная эфемерида.** Для прод-точности подключите библиотеку эфемерид (напр. Swiss Ephemeris) на бэке и подставьте реальные положения планет/домов в те же секции UI.

## Чеклист реализации бэкенда (что нужно для прода)

1. **Telegram Mini App init**: валидировать `initData` (HMAC по bot token), извлечь user id / имя / username / аватар → заполнять профиль. Не доверять клиентским данным профиля.
2. **БД**: пользователи (баланс, дата free, выбранная колода, дата карты дня), транзакции, гадания (история с картами и текстом трактовки).
3. **Эндпоинт «сделать расклад»** (атомарно на сервере): проверить право (free/баланс) → списать → разыграть карты (сервер, не клиент) → вызвать LLM по промпту выше → сохранить в историю → вернуть карты + трактовку. ThinkingScreen показывается, пока идёт запрос.
4. **LLM-прокси**: ваш ключ, тот же промпт и JSON-схема; ретраи и серверный фолбэк на статические тексты.
5. **Платежи**: реальное пополнение баланса. Варианты для TG Mini App: **Telegram Stars / Telegram Payments**, либо внешний провайдер (ЮKassa/СБП/карты). По вебхуку об оплате — начислить `amount+bonus`, записать транзакцию.
6. **Карта дня**: серверная фиксация по дате на пользователя.
7. **Натальная карта**: (опц.) реальные эфемериды для точности.
8. **Контент/лицензии**: изображения колод (`cards/mansion`, `cards/wood`) — сторонние; подтвердите права на коммерческое использование или замените на свои.

## Design Tokens

Полный источник — `<style>` в `index.html` (три темы: `midnight` по умолчанию, `amethyst`, `emerald`). Ключевые переменные темы `midnight`:

| Токен | Значение | Назначение |
|---|---|---|
| `--bg1` | `#0a0a16` | основной фон |
| `--bg2` | `#141431` | вторичный фон / градиент |
| `--gold` | `#dcb86a` | основной акцент (золото) |
| `--gold-deep` | `#9c7a30` | тёмное золото |
| `--gold-line` | `rgba(220,184,106,~.2)` | тонкие золотые границы |
| `--glow` / `--glow-soft` | золотые свечения | радиальные подсветки, плавающее свечение |
| `--text` | светлый | основной текст |
| `--muted` | приглушённый | вторичный текст |
| `--panel` | тёмная панель | карточки/блоки |
| `--back-1` | фон иконок | подложки |

**Акценты раскладов** (`accent` в `SPREADS`): daily `#5fd0a0`, yesno/question/year `#dcb86a`, love `#e06a9a`, situation `#6aa7e0`, match `#c46ae0`, money `#cdae5e`, celtic/natal `#b89be8`.

**Типографика:**
- `Marcellus` (serif) — заголовки, названия, числа баланса.
- `Cormorant Garamond` (serif) — трактовки, описательный текст (часто italic).
- Системный sans — мелкий служебный текст, лейблы.
- Минимальные размеры: служебные лейблы ~10–12px, тело 14–17px, крупные заголовки 18–46px.

**Скругления:** карточки 14–20px; карты ~7% ширины. **Тени:** мягкие тёмные + золотые свечения. **Хит-таргеты:** ≥44px.

**Ключевые анимации** (keyframes в `index.html`): `screenIn` (вход экрана), `floatGlow` (плавающее золотое свечение по нижней кромке), `fateGlow` (вспышка «довериться случаю»), `pulse` (индикатор загрузки ИИ), `aiSheen` (мерцание скелетонов), `drawLine` (рисование линий натальной карты), flip карт (3D), `.sheen-band` (переливающийся блик на премиум-баннерах).
